# 📔 DevDiary

**DevDiary** — это консольное приложение для ведения заметок разработчика. Оно помогает сохранять технические записи, организовывать их с помощью **тегов** и быстро находить нужную информацию через **поиск**. Заметки хранятся локально и доступны прямо из терминала.

## ✨ Возможности

- 📝 Создание, просмотр, редактирование и удаление заметок.
- 🏷️ Добавление тегов для группировки записей.
- 🔍 Поиск заметок по заголовку и содержимому.
- 📅 Просмотр заметок по дате создания.
- 📤 Экспорт заметок в JSON.
- 💾 Локальное хранение данных.
- ⚡ Управление заметками из командной строки.

## 🚀 Установка

1. Установите Python версии 3.10 или выше.
2. Скачайте или клонируйте репозиторий.
3. Перейдите в каталог проекта.
4. Запустите приложение.

```bash
git clone https://github.com/example/devdiary.git
cd devdiary
python --version
python main.py
```

> **Примечание:** в учебной версии DevDiary используется только стандартная библиотека Python, поэтому устанавливать дополнительные пакеты не требуется.

## 💻 Использование

Пример запуска приложения и добавления заметки:

```bash
python main.py add "Изучение Python" --tag python --tag study
python main.py list
python main.py search "цикл"
python main.py export --format json
```

### Команды CLI

| Команда | Описание |
|---|---|
| `add` | Создать новую заметку |
| `list` | Показать все заметки |
| `show <id>` | Открыть заметку по идентификатору |
| `edit <id>` | Изменить заметку |
| `delete <id>` | Удалить заметку |
| `search <текст>` | Найти заметки по тексту |
| `export` | Экспортировать заметки |

## 🏗️ Архитектура

> DevDiary разделяет работу с командами пользователя, обработку заметок и хранение данных.
>
> Каждая часть отвечает за отдельную задачу, поэтому приложение проще тестировать и расширять.

```text
DevDiary
├── main.py          # Точка входа и CLI
├── notes.py         # Создание и обработка заметок
├── storage.py       # Чтение и запись данных
├── search.py        # Поиск заметок
└── data/
    └── notes.json   # Локальное хранилище
```

Вложенная цитата:

> Основной принцип проекта:
>> одна часть программы — одна зона ответственности.
